# DFDL33_SH8619协议转换单元上位机

Windows 桌面串口工具，支持直接收发和双串口透明代理监听，可解析 **Modbus RTU主机请求**以及 **DL/T 645-2007主机请求和从机响应**。

## 直接使用

双击 `release/DFDL33_SH8619协议转换单元上位机_V1.0.25.exe` 即可运行。该文件已经包含运行环境，目标电脑不需要安装 Python。

上位机名称和版本统一定义在`app_version.py`，窗口标题及exe文件名均从该文件取值。每次正式功能调整发布时递增末位版本号一次，重试打包和程序启动不递增，且与单片机固件版本独立。历史exe不自动删除。

图标源文件为`assets/app_icon.png`。打包时移除完全透明的外围留白，保留比例及透明度并添加安全边距，独立生成16～256像素的16种尺寸图标，同时嵌入exe和窗口图标。Windows运行时按窗口DPI选取标题栏和任务栏图标，避免放大小尺寸图标。替换外部PNG不会改变已有exe，必须重新打包；原PNG保持不变。

正常关闭时将645地址及串口参数保存到exe同目录的`serial_assistant_settings.json`，下次启动恢复，地址字符串保留前导零。版本exe在同目录继续共用原设置，发布时不覆盖用户设置；迁移到新目录时需一并复制设置文件。多个版本同时运行时以最后关闭的保存值为准。强制结束进程不会执行关闭保存，目录不可写时会提示保存失败。

## 代理监听接线和设置

Windows 通常不允许两个程序同时打开同一个 COM 口，因此监听其他串口软件时需要先创建一对虚拟串口。假设虚拟串口对为 `COM10 ↔ COM11`，真实 USB/RS485 串口为 `COM3`：

1. 原串口软件连接 `COM10`，串口参数保持不变。
2. 本工具选择“代理监听”模式。
3. “代理端口”选择 `COM11`，“设备端口”选择 `COM3`。
4. 打开串口后，工具透明转发 `COM10/COM11 ↔ COM3` 的数据。
5. 选择协议或使用“自动识别”；645的主机请求及从机回复均会解析，所有数据仍原样透明转发。

工具提供“自动创建虚拟串口对”按钮：如果已经安装 com0com，它会自动寻找空闲的连续 COM 号、请求管理员权限创建，并将工具端自动填入代理端口。如果未检测到 com0com，会询问是否打开其官方项目下载页。

虚拟串口属于 Windows 内核设备，本程序不会静默下载或安装驱动。首次使用仍需由用户确认安装受信任的 com0com（或同类驱动）。不要让原串口软件和本工具选择虚拟串口对的同一端。

## 功能

- 串口参数：端口、波特率、数据位、停止位、奇偶校验
- 关闭窗口时自动保存模式、协议、串口和串口参数，下次启动自动恢复
- 双串口透明代理，监听其他串口软件与真实设备之间的双向通信
- 自动检测 com0com、选择空闲端口号并通过 UAC 创建虚拟串口对
- HEX 或 UTF-8 文本发送，可自动追加 Modbus CRC
- 协议可选择“自动识别”“Modbus RTU”或“DL/T 645-2007”
- 接收报文以 HEX 显示，并解析设备地址、读/写操作、功能码、寄存器/线圈起始地址、数量
- 接收线程先等待 RTU 帧间隔，再对驱动缓冲区执行一次整帧读取，串口监听器不会显示为首字节和后续字节两次读取
- CRC-16/Modbus 校验，同时显示报文携带值与计算值
- 校验设备地址、寄存器/线圈数量、批量写字节数和值域，结构异常报文标红
- 支持功能码 `01`、`02`、`03`、`04`、`05`、`06`、`08`、`0F`、`10`、`16`、`17`
- 生成并发送645读通信地址报文，自动回填从机回复的12位通信地址
- 使用电脑本地时间生成或直接发送`0x08`广播校时报文，记录中显示实际校时时间
- 按数据标识生成645读数据和写数据报文，自动处理地址/数据标识线序、`+0x33`及校验和
- 支持`06000001`给定时间负荷记录块，可填写块数和起始时间，并识别仅回显DI的正常空应答
- 解析645前导FE、地址、控制码、正常/异常响应、数据标识、数据区、帧序号和CS校验
- 直接收发模式支持根据“有后续数据”标志自动读取后续帧；代理模式只解析，不干预原主站
- 写数据的密码权限、密码和操作者代码使用配置文件默认值，不在操作界面显示
- 标准与厂商扩展数据标识统一使用UTF-8 JSON配置，可配置读写权限和数据区字段结构
- 数据标识按“标准645/扩展645、标识组、具体标识”分级选择，扩展标识支持连续范围和离散后缀
- 复杂数据域可复用JSON结构体；写入时自动生成字段表单，读取结果双击记录可查看结构化详情
- 无串口设备时也可用“手动解析 HEX”验证报文

## DL/T 645-2007操作

1. 协议选择“DL/T 645-2007”或“自动识别”。
2. 打开真实串口；如果只监听其他软件，则按上面的代理监听方式连接。
3. 在“DL/T 645操作”页点击“读取通信地址”，或手工填写12位地址。
4. 选择“读”及数据标识，点击“生成并发送”。
5. 写操作选择“写”，程序会根据数据标识配置动态显示写入字段，填写后生成并发送。
6. 从机回复会在记录表中显示数据标识描述、字段值、单位、异常原因和校验结果。

“读取通信地址”使用广播地址，建议总线上只有一个待识别设备，避免多个设备同时响应冲突。

“生成校时报文”使用点击时的电脑本地时间生成预览；“广播校时（电脑时间）”会在每次点击时重新获取本地时间并立即发送。校时使用广播地址`AAAAAAAAAAAA`及控制码`0x08`，六字节BCD数据按秒、分、时、日、月、年排列，不含数据标识、密码或操作者代码，前导FE数量沿用界面设置。该命令作用于总线上支持广播校时的设备，不返回应答；可随后读取日期及时间核对结果。直接校时按钮不会发送之前预览中的旧时间。

电压校准位于“扩展645 → 通信与设备维护”，选择写操作及`04000D00`“电压校准（写1执行）”，执行值默认且仅允许`1`。发送报文沿用标准写数据的密码和操作者代码字段；设备调用`voltage_calibration()`后回复正常写应答，只表示校准请求已受理，不表示实际校准及保存已经完成。该数据标识不支持读取，现有电压校准算法保持不变。

## 事件读取（V1.0.25，0923v1附录D）

V1.0.25保留7类事件的14个独立标识组，统一采用“DI按字节加空格 | 名称”的显示格式，与参数类一致，例如 `03 E6 00 xx | 开关机控制事件总次数`、`03 E6 01 xx | 开关机控制事件数据块`。次数组选逆变器1～12/全部12台次数块，数据块组选上1～50次记录；电压越限次数组为固定 `03 E6 11 00 | 电压越限事件总次数`。本版仅修改显示文字，429个DI、分组、业务字段及报文解析不变。

选择“读 → 事件类 → 事件分组 → 具体标识”，核对地址和串口参数后生成/发送；不接设备时可以只生成报文或手动解析HEX。历史记录不是控制命令，也不会清除事件。

| 事件 | 总次数DI | 上1～50次记录DI | 记录业务长度（不含DI） |
| --- | --- | --- | --- |
| 开关机 | 03E600xx | 03E601nn | 36 |
| 有功功率 | 03E602xx | 03E603nn | 73 |
| 无功功率 | 03E604xx | 03E605nn | 73 |
| 功率因数 | 03E606xx | 03E607nn | 48 |
| 有功时段 | 03E608xx | 03E609nn | 73 |
| 电压越限 | 03E61100 | 03E611nn | 24 |
| 通信异常 | 03E612xx | 03E613nn | 13 |

- `xx=01～0C`为逆变器号，`FF`是12台次数块（每台3字节BCD），不是次数求和。电压越限为装置级计数。
- `nn=01～32`为历史序号，十六进制32代表上50次；历史读取不支持FF全选。
- 时间按6字节低字节在前BCD解析；12台状态/数值按逆变器1～12还原，界面按设备分行，双击报文可查看逐字段详情。HEX保留原始帧供核对。
- 调控结果：00成功、01未调、02失败、03不支持、04其他；FF显示“无此信息”，不等于未调或0。
- 事件有功/无功/时段调控值为4字节、4位小数，单位随事件类型切换kW/kvar或%，不能使用普通2字节百分比格式。数值符号位沿用645控制点BCD约定，现场需与设备报文核对。
- 事件响应执行精确长度、BCD及日期时间检查；非法数据不显示为成功记录，未知枚举保留未知值。
- 正文部分要求保存100次，但附录只定义上50次读取，因此不自行扩展第51～100次。清零、升级、校时历史缺少DI和结构，本版不补造；功率因数示例文字矛盾按明确枚举定义解释。
- 上位机支持解析不代表当前固件已实现事件。异常应答/无响应需核查固件；本次不增加固件、主动上报、阈值写入或批量导出。
- 发布需同时更新EXE与同目录JSON（源码与release字典同步）。旧外部JSON优先于内置字典，若仍看到空事件分类请备份现场自定义字典后使用新版字典；串口设置文件不覆盖。旧EXE保留，但不保证旧版解析器能识别新版事件配置，请使用V1.0.25。

## 数据标识配置

配置文件为 `dlt645_data_identifiers.json`。打包版首次启动时会尝试将内置配置复制到EXE同目录，发布目录中也附带一份可直接编辑的配置文件。修改后点击“重新加载配置”即可生效。

每个数据标识包含：

- `di`：8位逻辑数据标识，程序统一处理线上低字节在前和`+0x33`。
- `description`：中文描述。
- `access`：`read`、`write`或`read_write`。
- `read_response.fields`：读取回复的数据区结构。
- `read_request.fields`：特殊读取请求在DI后携带的参数结构。
- `write_request.fields`：写入请求的数据区结构。

字段按减去`0x33`后的线上数据区顺序排列，支持：

- `bcd`：BCD数值，可配置长度、小数位、字节序、比例、偏移、单位和符号位。
- `uint` / `unsigned_integer`：无符号整数。
- `int` / `signed_integer`：有符号整数。
- `enum`：枚举值。
- `bit_field`：位状态。
- `ascii`：定长字符串。
- `hex` / `raw_bytes`：定长原始字节。
- `hex_uint`：按配置字节序传输的十六进制无符号整数，读取时统一显示为`0xXXXX`。

全局 `defaults` 可配置隐藏的写安全字段：

```json
{
  "password_permission": "00",
  "password": "000000",
  "operator_code": "00000000",
  "write_include_security": true,
  "preamble_count": 4
}
```

扩展数据标识组可以用一个三字节前缀加连续范围、离散值来配置，例如：

```json
{
  "prefix": "04E604",
  "display": "04 E6 04 xx | 逆变器运行状态",
  "suffixes": {
    "range": {"from": "01", "to": "0C"},
    "values": ["FF"]
  },
  "read_schema": "inverter_status"
}
```

公共字段结构放在顶层`schemas`中，具体数据标识通过`read_schema`和`write_schema`引用。支持BCD、日期时间、整数、浮点数、ASCII、枚举、位域、原始HEX和TTTT类型描述符。类型描述符在写入界面中拆分为数据类型、字节序和小数位数，由程序自动合成。

如果目标设备使用不带密码和操作者代码的厂商扩展写格式，可将 `write_include_security` 设为 `false`。

## 运行

```powershell
cd tools\serial_assistant
python -m pip install -r requirements.txt
python app.py
```

重新生成 EXE：

```powershell
python -m pip install pyinstaller Pillow
python -m PyInstaller --noconfirm --clean --distpath release --workpath build 串口Modbus解析工具.spec
```

运行测试：

```powershell
python -m unittest -v
```

示例：`01 03 00 00 00 02 C4 0B` 将解析为设备地址 1、读保持寄存器、起始地址 0、数量 2、CRC 正确。
